# 백오피스 1차 작업 지시서 (목데이터 버전)

작성일 2026-11-25 · 대상: 위드더레이크 백오피스 1차 화면 (홈, 캘린더, 진행 현황, 팀 현황)

이 문서는 백오피스 첫 화면을 **목데이터로 만들어 배포까지** 하기 위한 작업 지시서입니다. Claude Code에서 이 문서를 읽고 순서대로 진행합니다. 시안 이미지는 같은 `docs/` 폴더의 `backoffice-mockup-*.png`입니다.

---

## 0. 작업 원칙 (반드시 지킬 것)

- 작업 전에 무엇을 어떻게 할지 먼저 말하고 허락을 받은 뒤 진행합니다.
- 커밋과 푸시는 지시가 있을 때만 합니다. 푸시는 사용자가 직접 합니다.
- 작업 브랜치는 `feat/backoffice`입니다. 그 밖의 브랜치·폴더는 임의로 만들지 않습니다.
- 새 라이브러리는 도입 전에 먼저 물어봅니다. ('3. 기술 구성'에 적힌 것만 사전 승인됨)
- 중복 코드를 줄이고 재사용하기 쉽게 만듭니다. 주석은 꼭 필요한 곳에만 답니다.
- 커밋 메시지는 한 줄, 명사형으로 끝냅니다. 예: `백오피스 캘린더 화면 구현`
- 답변과 문서는 한국어, 합니다체로 작성합니다.

**목표**: 노션·구글 캘린더를 아직 연결하지 않은 상태에서, 목데이터로 백오피스 화면 4개를 만들고 Cloudflare Pages에 올려 팀이 미리 사용해 볼 수 있게 합니다. 사용자는 40대 직원 기준이며, 설명 없이도 바로 사용할 수 있는 화면과 문구를 목표로 합니다.

**'내 할 일' 메뉴는 두지 않습니다.** 내 업무는 홈의 '내 업무' 칸과 진행 현황(담당자 기본값 = 나)에서 확인합니다.

## 5. 데이터 구조와 목데이터

### 5-1. 데이터 형식 (`types.ts`)

```ts
type Member = { id: string; name: string; short: string; role: string };   // short: 동그라미 안 이름 (예: "미경")
type TaskStatus = "todo" | "doing" | "review" | "done";                     // 시작 전 / 진행 중 / 확인 필요 / 완료
type Task = {
  id: string; title: string; status: TaskStatus;
  assigneeId?: string;                                                      // 없으면 '미지정'
  due: string;                                                              // YYYY-MM-DD
  important: boolean;
  meetingId?: string;                                                       // 관련 회의
  description?: string;
  subtasks?: { title: string; done: boolean }[];
  notionUrl?: string;
};
type Meeting = { id: string; title: string; date: string };                 // 예: "11월 24일 주간 회의"
type WeeklyGoal = { id: string; week: string; title: string; ownerId: string; done: boolean };  // week: "2026-W48"
type CalendarEvent = {
  id: string; title: string; date: string; time?: string;
  ownerId: string | "all";                                                  // all = 전체
  important?: boolean;                                                      // 홈 '중요 일정'에 표시
};
```

`data/index.ts`는 `getMembers()`, `getTasks()`, `getMeetings()`, `getWeeklyGoals(week)`, `getEvents(month)` 함수만 내보냅니다. 지금은 `mock.ts`를 돌려주고, 나중에 노션·구글 캘린더 연결 시 이 파일만 바꿉니다.

### 5-2. 목데이터 기준

| 항목 | 기준 |
| --- | --- |
| 구성원 | 정미경(대표), 김민주(PM), 김진(팀원) |
| 현재 사용자 | 김진 (상단 '사용자 김진 ▾'에서 변경) |
| 기관명 | 실제 기관명 대신 'A기관 미팅', 'B요양원 협의'처럼 일반 표현 |
| 기간 | 2026년 11월 (오늘 = 2026-11-25 수요일, 48주차 = 11.23~11.29) |
| 양 | 업무 25~30개(3명 분산, 상태 4종 섞기), 회의 4~5개, 주간 목표 4개(48주차), 일정 15~20개, 중요 일정 5개 |
| 꼭 넣을 경우 | 마감 지난 업무 2개, 담당자 미지정 업무 1개, 중요 업무 여러 개, 완료 업무 몇 개, 세부 업무가 있는 업무 1개 |

시안 이미지의 내용(제목, 날짜, 분포)을 참고해 목데이터를 만듭니다.

## 6. 디자인 기준

시안 이미지를 그대로 따릅니다.

**색은 세 가지만 사용**

| 용도 | 색 |
| --- | --- |
| 기본 (배경, 글자, 선) | 흰색·회색 계열 (배경 #f9fafb, 선 #e5e7eb, 보조 글자 #6b7280, 본문 #111827) |
| 강조 (오늘 날짜, 진행률 막대만) | 보라 #410099 |
| 경고 (마감 지남, 3일 이하 남은 중요 일정, 담당자 미지정만) | 빨강 #dc2626 |

- 사람을 색으로 구분하지 않습니다. 이름은 글자나 회색 동그라미(짧은 이름)로 표시합니다.
- 글자는 크게 합니다. 본문 14.5px, 카드 제목 16px, 페이지 제목 26px 안팎, 버튼 높이 38px.
- 사이드바는 흰 바탕, 선택된 메뉴만 검정 배경에 흰 글자입니다.
- 주요 버튼(+ 업무 추가)은 검정 배경입니다.
- 글꼴은 Pretendard입니다.

**필터 방식**

- 항목이 2~3개로 고정된 것(구분: 전체·일정·업무)은 나란히 놓은 버튼으로 표시합니다. 선택된 것만 검정 배경입니다.
- 사람처럼 늘어날 수 있는 것(담당자)이나 항목이 많은 것(관련 회의, 상태)은 드롭다운 버튼으로 표시합니다. 버튼 문구는 `담당자: 전체 (3명) ▾` 형식입니다.
- 담당자 드롭다운을 열면 이름 검색, 체크 목록(본인은 `김진 (나)`로 맨 위), 전체 해제, 적용 버튼이 있습니다.
- 켜고 끄는 조건은 체크박스로 표시합니다. 예: 완료된 업무 숨기기, 마감 지난 업무만

**문구 규칙**

- 사용하는 단어: 일정, 업무, 담당자, 마감일, 관련 회의, 미지정, 시작 전, 진행 중, 확인 필요, 완료, 업무 추가
- 사용하지 않는 단어: 콘텐츠, 할 일, 이슈, 태스크
- 질문형·대화형 문구('무엇을 볼까요?', '누구 것을?')를 사용하지 않습니다. 항목 이름은 명사로 짓습니다.
- 설명 문장은 합니다체입니다. 예: "회사 일정과 업무 마감일을 한 달력에서 확인합니다."
- 개수는 '건'으로 셉니다. 예: 업무 4건, 8건 중 3건 완료
- 날짜는 `11월 27일 (금)` 형식입니다.

## 7. 화면별 상세

### 7-1. 홈 (`/`)
- 인사말 "김진 님, 안녕하세요"와 요약 한 줄: `11월 25일 (수) · 오늘 마감 업무 2건 · 마감 지난 업무 1건`
- 카드 5개
  - **내 업무**: 체크박스, 업무명, 마감일(오늘이면 '오늘', 지났으면 빨간 '마감 지남'). 링크 '진행 현황 →'
  - **중요 일정** (2주 이내): 'n일 남음'(3일 이하 빨강), 일정명, 날짜
  - **오늘 일정**: 시간, 일정명, 담당자. 링크 '캘린더 →'
  - **이번 주 팀 목표**: 'n건 중 n건 달성', 진행률 막대, 목표 목록(체크, 담당자)
  - **이번 주 마감 업무 (팀 전체)**: 마감일, 업무명, 담당자, 상태 표시. 링크 '진행 현황 →'
- 체크하면 완료로 바뀌고 취소선. 목데이터 단계에서는 화면 상태만 바뀌고 새로고침하면 원래대로

### 7-2. 캘린더 (`/calendar`)
- 월 보기(월요일 시작), 이전 달·다음 달·오늘 버튼
- 필터 영역
  - 구분: 전체 · 일정 · 업무
  - 담당자 드롭다운 (기본: 전체)
  - 완료된 업무 숨기기 (체크박스)
  - 아래에 범례: 회색 칸 = 일정, ☐ = 업무(완료 시 ☑), 빨간 글씨 = 마감 지남
- 날짜 칸: 일정은 회색 배경 한 줄, 업무는 체크 표시 + 업무명. 넘치면 '그 외 n개'
- 오늘 날짜는 보라 원
- 오른쪽 카드: 선택한 날짜의 '일정 n건', '업무 n건' 목록, '+ 업무 추가', '구글 캘린더에 일정 추가' 버튼

### 7-3. 진행 현황 (`/progress`)
- 필터: 업무명 검색, 담당자 드롭다운(기본: 나), 관련 회의 드롭다운, 체크박스 3개(마감 지난 업무만, 중요 업무만, 담당자 미지정만)
- 상태별 열 4개: 시작 전 · 진행 중 · 확인 필요(검토, 결재 대기) · 완료(최근 2주). 열 제목 옆에 개수
- 업무 카드: '중요' 표시, 업무명, `담당자 · 이름`(미지정이면 빨강), `마감 · 날짜`(지났으면 빨강), 열 아래 '+ 업무 추가'
- 카드를 누르면 오른쪽 상세 영역: 진행 상태(드롭다운), 담당자(변경), 마감일, 관련 회의, 내용, 세부 업무(체크), '노션에서 보기 ↗'
- 화면 아래 안내: "업무 카드를 누르면 오른쪽에서 진행 상태, 담당자, 마감일을 변경할 수 있습니다. 변경 내용은 노션에도 저장됩니다." (목데이터 단계에서는 화면 상태만 변경)
- 열 이름과 상태 값은 노션 업무 표의 실제 상태 값을 받으면 맞춰 바꿉니다.

### 7-4. 팀 현황 (`/team`)
- 기간 전환: 이번 주 · 지난주 · 이번 달
- 구성원 카드 3개: 이름, 역할, `n건 중 n건 완료 (%)`, 진행률 막대, 마감 지난 업무 수(1 이상이면 빨강), 담당한 이번 주 팀 목표
- 아래 표 '이번 주 업무 목록': 담당자 · 업무 · 마감일 · 상태. 오른쪽에 담당자 드롭다운, 상태 드롭다운

### 7-5. 공통 동작
- 상단 오른쪽 '사용자 김진 ▾': 구성원 중 하나를 고르면 홈의 내 업무와 진행 현황의 기본 담당자가 그 사람 기준으로 바뀝니다. 선택은 브라우저(localStorage)에 기억합니다.
- 상단 왼쪽: '최종 업데이트 오후 2:25'(목데이터에서는 고정 문구) + 새로고침 버튼
- 모든 페이지 `noindex` (`robots: { index: false, follow: false }`)

## 8. 현재 코드 상태와 정리할 것

`backoffice/`는 예전 지시서(할 일, 콘텐츠 캘린더 기준)로 이미 만들어져 있고, 루트 `tsconfig.json`·`eslint.config.mjs`의 제외 설정(4번)도 끝난 상태입니다. 새로 만들지 말고 아래 기준으로 고칩니다.

**그대로 사용 (문구·스타일만 조정)**
- `layout.tsx`, `lib/date.ts`
- `components/`: `MonthCalendar`, `Checkbox`, `ProgressBar`, `PageHeader`, `Card`, `Avatar`, `Button`

**삭제**
- `app/todo/` (할 일 화면). 단, `WeeklyGoalsCard`는 홈의 '이번 주 팀 목표' 카드로 옮겨 재사용
- `app/content/` (콘텐츠 캘린더 전체)
- `components/SourceTag` (노션/직접 구분 표시)
- `types.ts`의 콘텐츠 관련 타입·상수 (`ContentItem`, `CONTENT_CATEGORIES`, `CONTENT_STATUSES`, `CATEGORY_SHORT`), `NotionLinks`의 `contents`

**수정**
- `AppShell`: 메뉴 4개(홈·캘린더·진행 현황·팀 현황)와 '다음에 추가될 메뉴', 선택 메뉴 검정 배경, 경로 표시(Breadcrumb) 제거, 상단에 '최종 업데이트·새로고침'과 '사용자 김진 ▾'. 사이드바 아래 '보는 사람' 선택은 상단 사용자 선택으로 옮김
- `lib/viewer.tsx` → `lib/user.tsx`로 이름 변경, '현재 사용자' 의미로 정리
- `FilterBar` → `ToggleGroup`으로 이름 변경 (나란히 놓은 버튼)
- `Segmented`: 팀 현황 기간 전환에만 사용
- `lib/data/`: 5번 형식과 실명 목데이터로 다시 작성
- `app/calendar/CalendarView`: 7-2 기준 (구분, 담당자 드롭다운, 완료된 업무 숨기기, 날짜 칸에 업무 표시, 오른쪽 날짜별 상세)
- `app/team/TeamView`: 7-4 기준 (문구, 담당자·상태 드롭다운)

**새로 만들기**
- `app/page.tsx` 홈 (지금은 `/todo`로 이동만 함)
- `app/progress/` 진행 현황
- `components/Dropdown`, `components/MemberDropdown`, `components/StatusBadge`

**실행 환경 참고**: 화면 확인은 맥에서 `cd backoffice && npm run dev`로 합니다.
