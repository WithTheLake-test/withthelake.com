# 백오피스 2차 작업 지시서 (노션 구조 반영, 읽기 전용)

작성일 2026-11-26 · 대상: 위드더레이크 백오피스 (홈, 캘린더, 진행 현황, 팀 현황)

1차에서는 목데이터로 화면 4개와 체험판(수정·추가·저장)을 만들어 Cloudflare Pages에 배포했습니다. 이후 실제 노션 구조를 확인했고, 운영 방향이 아래처럼 정해졌습니다.

- 노션 업무 표와 콘텐츠 캘린더 표는 **백오피스에서 읽기만** 하고, 수정은 노션에서 합니다.
- 회사 일정은 계속 **구글 공유 캘린더**에서 관리합니다.
- 담당자는 노션 계정이 아니라 **이름 선택(대표님, 김민주, 김진)**으로 통일합니다.

이번 작업은 **노션 구조에 맞춘 목데이터로 화면을 읽기 전용으로 바꾸는 것**입니다. 실제 노션·구글 캘린더 연결은 다음 단계(10번)에서 합니다. 시안은 같은 `docs/` 폴더의 `backoffice-mockup-*.png`입니다.

## 0. 작업 원칙 (반드시 지킬 것)

- 작업 전에 무엇을 어떻게 할지 먼저 말하고 허락을 받은 뒤 진행합니다.
- 커밋과 푸시는 지시가 있을 때만 합니다. 푸시는 사용자가 직접 합니다.
- 작업 브랜치는 `feat/backoffice`입니다. 그 밖의 브랜치·폴더는 임의로 만들지 않습니다.
- 새 라이브러리는 도입 전에 먼저 물어봅니다.
- 중복 코드를 줄이고 재사용하기 쉽게 만듭니다. 주석은 꼭 필요한 곳에만 답니다.
- 커밋 메시지는 한 줄, 명사형으로 끝냅니다. 예: `백오피스 읽기 전용 화면 전환`
- 답변과 문서는 한국어, 합니다체로 작성합니다.
- 이 저장소의 Next.js는 최신 버전이라 코드 작성 전에 `node_modules/next/dist/docs/`를 확인합니다.

## 2. 노션 표 구조와 대응

### 2-1. 위드더레이크 업무 표

구조: 카테고리(개발·운영·정부지원과제) → 프로젝트 → 하위 업무. 프로젝트와 하위 업무는 '상위 항목'·'하위 항목' 관계형 속성으로 연결됩니다.

| 노션 속성 | 종류 | 값 | 백오피스 |
| --- | --- | --- | --- |
| 작업명 | 제목 | | 업무명 |
| 목표일정 | 날짜 (시작 → 끝) | | 마감일 = 끝 날짜 (끝이 없으면 시작 날짜). 없으면 마감일 없음 |
| 진행상태 | 상태 | 준비, 진행중, 완료 (전체 값 확인 중) | 진행 현황의 열 |
| 중요도 | 선택 | 높음 등 (전체 값 확인 중) | '중요' 표시는 높음일 때만 |
| 담당자 | 다중 선택 | 대표님, 김민주, 김진 | 담당자 (여러 명) |
| 카테고리 | 선택 | 개발, 운영, 정부지원과제 | 필터, 보조 표시 |
| 구분 | 선택 | 프로젝트, 할 일, 마감·제출, 행사·미팅 | 카드 표시, 필터 |
| 상위 항목 / 하위 항목 | 관계형 | | 프로젝트명 표시, '같은 프로젝트 업무' |
| 회의록 | 관계형 | | 상세의 '회의록' |
| 메모, 주관기관·파트너 | 텍스트 | | 상세에 표시 |
| D-day, 정렬키 | 수식 | | 사용하지 않음 (백오피스에서 계산) |
| 작업ID | 고유 ID | WTL-WORK-8 형식 | 사용하지 않음 |

## 3. 데이터 형식 (`lib/data/types.ts`)

기존 형식을 아래로 바꿉니다. 노션 값은 한글 그대로 둡니다.

```ts
type Member = { id: string; name: string; short: string; role: string; notionName: string }; // notionName: "대표님" 등

type TaskStatus = "준비" | "진행중" | "완료";          // 노션 진행상태 값 그대로. 값이 추가되면 여기만 수정
type TaskCategory = "개발" | "운영" | "정부지원과제";
type TaskKind = "프로젝트" | "할 일" | "마감·제출" | "행사·미팅";

type Task = {
  id: string; title: string;
  status: TaskStatus; important: boolean;          // important = 중요도 "높음"
  assigneeIds: string[];                           // 여러 명
  start?: string; due?: string;                    // YYYY-MM-DD, 목표일정 시작·끝
  category: TaskCategory; kind: TaskKind;
  parentId?: string;                               // 상위 항목(프로젝트)
  meetingTitle?: string;                           // 회의록
  memo?: string; partner?: string;
  notionUrl: string;
};

type PublishStatus = "사진수급필요" | "대기" | "작성중" | "발행대기" | "발행완료";
type PublishCategory = "기사PR" | "홈페이지" | "카톡정기메세지" | "N블로그" | "인스타그램";
type PublishItem = {
  id: string; title: string; date?: string;
  status: PublishStatus; category: PublishCategory;
  assigneeIds: string[]; notionUrl: string;
};

type CalendarEvent = { id: string; title: string; date: string; time?: string; ownerId: string | "all" }; // 구글 캘린더

type AppData = { members: Member[]; tasks: Task[]; publishes: PublishItem[]; events: CalendarEvent[] };
```

- 삭제: `Meeting`, `WeeklyGoal`, `NewTask`, `subtasks`, `description`, `doneOn`, `review` 상태
- 프로젝트명은 `parentId`로 찾은 상위 업무의 제목입니다. 상위 항목이 없는 업무는 카테고리를 대신 표시합니다.

### 목데이터 (`lib/data/mock.ts`)

시안에 나온 실제 업무명·프로젝트명을 사용합니다. 날짜는 '오늘' 기준 상대 날짜로 만들어, 시간이 지나도 화면이 비지 않게 합니다.

| 항목 | 기준 |
| --- | --- |
| 업무 | 18~22건. MG 함께자람 건강학교 프로젝트와 하위 업무 7건 포함. 카테고리 3가지, 구분 4가지, 진행상태 3가지를 모두 섞기 |
| 꼭 넣을 경우 | 마감 지난 업무 3~4건, 오늘 마감 1건, 담당자 2명 업무 여러 건, 중요도 높음 4~5건(2주 이내), 마감일 없는 업무 1건 |
| 발행 | 8~10건. 이번 주 4건 이상, 사진수급필요 1건, 담당자 미지정 1건, 발행완료 2건 |
| 일정 | 15~20건. 오늘 일정 3건 |

## 4. 현재 코드에서 바꿀 것

1차 체험판에서 만든 수정 기능을 걷어 내고 읽기 전용으로 바꿉니다.

**삭제**
- `components/TaskForm.tsx` (업무 추가·수정 폼)
- `app/WeeklyGoalsCard.tsx` (이번 주 팀 목표. 노션에서 가져올 곳이 정해지면 다시 추가)
- `components/Checkbox.tsx` (다른 곳에서 사용하지 않으면)
- `lib/store.tsx`의 수정 함수: `addTask`, `updateTask`, `toggleTaskDone`, `deleteTask`, `setGoalDone`, `reset`
- `lib/data/`의 localStorage 저장, 초기화 기능
- 체험판 안내 문구와 '체험용 데이터 초기화' 버튼

**유지**
- `lib/store.tsx`의 데이터 불러오기(`reload`)와 공유 구조. 상단 '새로고침' 버튼이 `reload`를 호출합니다.
- `lib/data/index.ts`가 유일한 데이터 진입점인 구조. 10번에서 이 파일만 노션·구글 캘린더 호출로 바꿉니다.
- `TODAY`가 실제 오늘 날짜인 것 (`lib/date.ts`)
- `Dropdown`, `MemberDropdown`, `ToggleGroup`, `Segmented`, `StatusBadge`, `Toast`, `MonthCalendar` 등 공통 요소

**새로 만들거나 바꿀 것**
- '노션에서 열기 ↗' 버튼: 업무·발행 항목의 `notionUrl`을 새 탭으로 엽니다.
- '노션에서 업무 추가 ↗', '구글 캘린더에서 일정 추가 ↗' 버튼: 노션 업무 표, 구글 캘린더 주소를 새 탭으로 엽니다. 주소는 `lib/links.ts` 한 곳에 상수로 둡니다. (목데이터 단계에서는 `#`)
- `StatusBadge`: 노션 진행상태 3가지와 발행 상태 5가지를 표시합니다.
- 남은 날짜 표시 함수: `n일 남음` / `오늘` / `n일 지남`(빨강) / `완료`

## 6. 화면별 상세

### 6-1. 공통
- 상단 왼쪽: `노션·구글 캘린더 최종 업데이트 오후 2:25` + 새로고침 버튼. 시각은 마지막으로 불러온 시각입니다.
- 상단 오른쪽: '사용자 김진 ▾'. 홈의 '내 업무' 기준이 바뀝니다.
- 담당자가 여러 명이면 `정미경, 김진`처럼 쉼표로 나열합니다. 자리가 좁으면 말줄임표로 줄입니다.

### 6-2. 홈 (`/`)
- 요약: `11월 26일 (목) · 7일 안에 마감할 내 업무 n건 · 마감 지난 내 업무 n건`
- 카드
  - **내 업무**: 업무명, 아래에 프로젝트명(없으면 카테고리), 오른쪽에 남은 날짜. 미완료를 마감일 순으로 보여 주고, 최근 완료는 흐리게 표시합니다. 최대 5건이며 링크는 '진행 현황 →'입니다.
  - **중요 일정**: 중요도 높음이고 2주 안에 마감하는 미완료 업무입니다. 'n일 남음'(3일 이하 빨강), 업무명, 프로젝트명, 날짜를 보여 줍니다.
  - **오늘 일정** (구글 캘린더): 시간, 일정명, 담당자
  - **이번 주 발행**: 날짜, 카테고리 약칭, 제목, 담당자(없으면 빨간 '미지정'), 상태. 링크는 '캘린더 →'입니다.
  - **마감 임박·지난 업무 (팀 전체)**: 마감 지난 미완료 업무와 이번 주 마감 미완료 업무입니다. 업무명, 프로젝트명, 담당자, 남은 날짜를 보여 줍니다.

### 6-3. 캘린더 (`/calendar`)
- 월 보기(월요일 시작), 이전 달·다음 달·오늘
- 필터
  - 구분: 전체 · 일정 · 업무 · 발행
  - 담당자 드롭다운
  - 완료된 항목 숨기기
- 범례: 회색 칸 = 일정(구글 캘린더), ● = 업무 마감일(노션), 점선 칸 = 발행 예정(노션), 빨간 글씨 = 마감 지남·사진 필요
- 날짜 칸
  - 업무는 마감일에만 표시합니다.
  - 완료 업무와 발행완료는 흐리게 표시합니다.
  - 마감 지난 업무와 사진수급필요는 빨강으로 표시합니다.
  - 항목이 넘치면 '그 외 n개'로 줄입니다.
- 오른쪽: 선택한 날짜의 '일정 n건', '업무 마감 n건', '발행 n건' 목록과 '구글 캘린더에서 일정 추가 ↗', '노션에서 업무 추가 ↗' 버튼

### 6-4. 진행 현황 (`/progress`)
- 오른쪽 위: '노션에서 업무 추가 ↗'
- 필터
  - 업무명 검색
  - 드롭다운: 담당자, 카테고리, 프로젝트, 구분
  - 체크박스: 마감 지난 업무만, 중요 업무만
- 열: 준비(시작 전) · 진행중(진행 중인 업무) · 완료(최근 2주). 열 제목 옆에 개수를 표시하고, 열 안은 마감일 순으로 정렬합니다.
- 카드
  - '중요'(높음일 때)와 구분 표시
  - 업무명, 프로젝트명(없으면 카테고리)
  - 담당자, `11월 24일 · 2일 지남`
- 카드를 누르면 오른쪽 상세 영역이 바뀝니다.
  - 진행상태, 담당자, 목표일정(남은 날짜), 프로젝트, 카테고리, 회의록, 메모
  - '같은 프로젝트 업무 (n건 중 n건 완료)' 목록: 상태와 업무명. 현재 업무는 굵게 표시합니다.
  - '노션에서 열기 ↗' 버튼
- 화면 아래 안내: "이 화면은 확인용입니다. 업무 추가와 수정은 노션에서 하고, 바꾼 내용은 몇 분 안에 반영됩니다. 바로 확인하려면 상단 새로고침을 누르세요."

### 6-5. 팀 현황 (`/team`)
- 기간 전환: 이번 주 · 지난주 · 이번 달
- 설명: "담당자별 업무 현황입니다. 한 업무에 담당자가 여러 명이면 각 담당자에게 모두 포함됩니다."
- 구성원 카드 3개: 이름, 역할, 진행 중 n건, (기간) 마감 n건, 마감 지남 n건(1 이상 빨강)
- 아래 표 '이번 주 마감·마감 지난 업무'
  - 열: 담당자, 업무, 프로젝트·카테고리, 마감일, 진행상태
  - 마감 지난 업무는 `진행중 · 마감 지남`처럼 빨강으로 표시합니다.
  - 오른쪽에 담당자·진행상태 드롭다운

## 11. 3차: 홈페이지 관리 (2차 작업이 끝난 뒤 진행)

홈페이지의 STORY 글과 IMPACT 항목을 코드 수정 없이 백오피스에서 고칠 수 있게 합니다. 예전에 `admin-test` 브랜치에서 홈페이지 안의 `/admin`으로 만들었던 기능을 백오피스로 옮기고, 최신 main 구조에 맞춥니다.

### 11-1. 화면

| 메뉴 | 주소 | 내용 | 시안 |
| --- | --- | --- | --- |
| 게시물 (STORY) | `/site/posts` | 글 목록: 카테고리, 제목 검색, 홈 노출 | `backoffice-mockup-5-posts.png` |
| 게시물 (STORY) | `/site/posts/edit?slug=` | 글 작성·수정: 본문 편집과 미리보기, 대표 이미지, 홈 노출, 삭제 | `backoffice-mockup-6-post-edit.png` |
| 성과 (IMPACT) | `/site/impact?tab=` | 탭별 항목 관리: 목록, 순서 변경, 오른쪽 수정 패널 | `backoffice-mockup-7-impact.png` |
| 성과 (IMPACT) | `/site/impact?tab=history` | 연도별 연혁 편집 | `backoffice-mockup-8-history.png` |

- **사이드바**: '업무'(홈, 캘린더, 진행 현황, 팀 현황)와 '홈페이지 관리'(게시물, 성과) 두 묶음으로 나눕니다.
- **상단 바**: 홈페이지 관리 화면에서는 '홈페이지 반영 상태: 반영 중 / 반영 완료 / 실패 · 시각'과 '홈페이지 열기 ↗'를 표시합니다.
- **디자인**: 5번 기준(흰 사이드바, 검정 선택·주요 버튼, 색 3가지)을 따릅니다. 삭제 버튼만 빨간 글자·테두리입니다.
- **성과 탭**: 지금 IMPACT 페이지 섹션 순서대로 둡니다.
  - 주요 프로젝트
  - 실증 현황
  - R&D·지식재산
  - 인증·수상·선정
  - 사회적 가치
  - 협력기관
  - 연혁
- **저장 방식**
  - 성과: 수정 패널의 '적용'은 화면에만 반영됩니다. 상단 '변경 사항 저장'을 눌러야 홈페이지에 반영됩니다. 저장하지 않은 변경 건수와 '되돌리기'를 표시하고, 저장하지 않고 나가려 하면 경고합니다.
  - 게시물: 글 수정 화면의 '저장'으로 바로 반영합니다.

### 11-2. 데이터 위치 (최신 main 기준)

- 글: `content/site-content.json`의 `story.items`. 형식은 `{ slug, category, title, date, image, excerpt, body: string[], featured }`입니다.
- 카테고리: `story.categories` (맨발걷기 정보, 힐링로드ON, NEWS, CONTENTS)
- 성과: 같은 파일의 `impact` (projects, leaderTraining, pilots, rnd, ip, certs, awards, programs, socialValue, partners, history, sections 등)
- 사진: `public/uploads/YYYYMMDD-이름.jpg`
- 자동 발행 기능도 `story.items`에 글을 추가합니다. 백오피스 목록에 함께 보여야 합니다.

### 11-3. 본문 편집 규칙

- 편집기는 텍스트 입력 + 도구 모음(소제목, 굵게, 링크, 목록, 번호 목록, 사진 넣기) + 미리보기입니다.
- 빈 줄로 나눈 덩어리 하나가 `body` 배열의 한 항목입니다.
- 미리보기는 홈페이지 `src/components/story/StoryBody.tsx`와 같은 규칙으로 그립니다. 같은 변환 함수를 홈페이지와 백오피스가 함께 사용하도록 한 곳에 둡니다.
- **선행 작업**: 홈페이지 글 표시 문제 4가지를 먼저 고칩니다. 홈페이지 main 브랜치 작업입니다.
  1. 헤더·푸터 메뉴에 CONTENTS 없음
  2. `## 소제목` 아래 본문까지 제목으로 표시됨
  3. 굵게·링크 미표시
  4. 번호 목록 미지원

### 11-4. `admin-test` 브랜치에서 옮길 것

`admin-test`는 main에 합치지 않습니다. 필요한 코드만 `git show origin/admin-test:<경로>`로 참고해 백오피스로 옮깁니다.

| 구분 | 파일 | 처리 |
| --- | --- | --- |
| GitHub 읽기·커밋 | `src/lib/admin/github.ts`, `server.ts`, `path.ts` | 백오피스 `functions/`·`lib/`로 옮김 |
| 반영 상태 | `functions/api/admin/deploy-status.ts`, `DeployStatus.tsx` | 옮김 (상단 바에 표시) |
| 성과 | `functions/api/admin/impact.ts`, `impact-schema.ts`, `components/admin/impact/*` | 옮김. 탭 구성은 schema 파일만 수정 |
| 사진 | `functions/api/admin/asset.ts`, `ImageInput.tsx`, `AdminImage.tsx`, `uploads.tsx` | 옮김 |
| 공통 입력 요소 | `FieldInput`, `StringListInput`, `SortableList`, `Drawer`, `useUnsavedWarning` | 옮기고 백오피스 디자인으로 변경 |
| 게시물 | `posts.ts`, `post.ts`, `MarkdownEditor.tsx` | **다시 만듦**. 마크다운 파일이 아니라 `story.items` 기준 |
| 홈페이지 `/admin` 화면, `ADMIN_ENABLED`, `*.admin.tsx` | | 사용하지 않음 |

### 11-5. 저장 구조

- 백오피스 Pages Functions(`backoffice/functions/api/site/`)가 GitHub API로 이 저장소에 커밋합니다.
- 커밋되면 홈페이지 Pages 프로젝트가 자동으로 다시 배포됩니다. 홈페이지 빌드 감시 경로에 `content/**`, `public/**`가 포함되어야 합니다.
- 자동 발행 기능과 같은 파일을 수정하므로 덮어쓰지 않게 합니다.
  - 저장할 때 최신 파일을 다시 읽어 바뀐 부분만 합칩니다.
  - 커밋 시 기준 커밋이 바뀌었으면 다시 시도합니다.
- 커밋 메시지는 한 줄 명사형입니다. 예: `STORY 글 수정: mgmmm-school`, `IMPACT 연혁 수정`
- 시크릿: `GITHUB_TOKEN`, `GITHUB_REPO`, `GITHUB_BRANCH`. Pages 시크릿과 `backoffice/.dev.vars`에 둡니다.
  - 토큰은 이 저장소만 대상으로 하는 Fine-grained 토큰입니다.
  - 권한: Contents 읽기·쓰기, Commit statuses 읽기
- **접근 제한 필수**: 홈페이지를 바꾸는 기능이므로, 저장 기능을 켜기 전에 Cloudflare Access를 반드시 설정합니다.

### 11-6. 진행 순서

1. 홈페이지 글 표시 문제 4가지 수정 (11-3)
2. 백오피스 사이드바 묶음, 홈페이지 관리 화면 4개 구현. 처음에는 저장 없이 main의 `site-content.json`을 읽어 화면만 확인합니다.
3. Cloudflare Access 설정, GitHub 토큰 등록 (사용자)
4. 저장·사진 올리기·반영 상태 연결. 테스트 브랜치로 먼저 저장해 보고, 확인 후 `GITHUB_BRANCH`를 main으로 바꿉니다.
5. 확인
   - `backoffice/`와 루트에서 각각 build, lint 통과
   - 글 저장 후 홈페이지 반영 확인
   - 자동 발행 글과 함께 저장해도 서로 덮어쓰지 않는지 확인
